# R46H v0.10 offline BOOT candidate

For the current 62,534,975,488-byte fast card, the preferred path is now the
target-side transaction in
[`../tools/r46h-v10-target-installer/README.md`](../tools/r46h-v10-target-installer/README.md).
It consumes the already raw-verified v0.10 payload from the rebuilt p3, keeps
the active v0.8 files byte-identical, and avoids another card removal. The
offline full-p1/Card Agent flow below remains the reviewed fallback if the
target-side preflight cannot prove its exact base state; it is not the first
choice and a whole-card rewrite is never a substitute.

`build-v10-p1-candidate.py` accepts the completed **install-modules-only**
v0.10 EASYROMS bundle and the exact full p1 image previously deployed for the
v0.9 one-shot test. It never opens a block device. All FAT changes happen on a
private copy below `mainline/out/.cache` with networking disabled.

The candidate keeps the active v0.8 `boot.ini`, Image and DTB byte-identical.
It removes only the audited v0.9 one-shot Image and boot script, then adds the
canonical v0.10 deterministic gzip Image, v0.10 DTB and a versioned one-shot
boot script. The separate v0.10 DTB is required because the full-range ADC
change is a device-tree change; a package whose DTB is byte-identical to the
v0.8 baseline is rejected.

The builder validates the bundle's exact payload allowlist, package archive,
Image/DTB relationships, current card profile, v0.8 baseline and clean-HEAD
source snapshot. It repeats those checks immediately before an atomic
no-replace publication. The input p1 is hashed before and after the build. Its
expected full SHA-256 is also copied into the write plan as
`target_sha256_before`, so Card Agent rejects a live p1 mismatch before
publishing `WRITE_IN_PROGRESS` or writing a byte.

After committing all v0.10 tooling and documentation, build the kernel and the
modules-only bundle from that clean HEAD:

```sh
mainline/scripts/build-kernel.sh \
  --build-id v0.10-adc-full-range \
  --root-spec PARTUUID=c9f931c9-02

python3 mainline/scripts/generate-easyroms-bundle.py \
  --package-tar mainline/out/r46h-mainline-test-v0.10-adc-full-range.tar.gz \
  --card-profile mainline/deploy/profiles/hl-r46h-v22-g92-31719424000-v1.json \
  --current-baseline mainline/deploy/baselines/v0.8-bootloader-handoff.json \
  --purpose adc-full-range-modules \
  --action-policy install-modules-only \
  --source-date-epoch 1785369600 \
  --output-dir mainline/out
```

Build the offline p1 candidate from the retained v0.9 full image:

```sh
python3 mainline/scripts/build-v10-p1-candidate.py \
  --input-p1 mainline/out/r46h-v09-p1-candidates/r46h-v0.9-p1-one-shot/p1-v0.9-one-shot.img
```

The input must be exactly 117,440,512 bytes with SHA-256
`800e3c9a9196c62a2c46726db694866091cbc396b7e156109e24ce7ef5ef9907`.
This is a historical baseline identity, not a hash of the new v0.10 output.
The resulting receipt must show two removals, three additions, no changed
pre-existing file, at least 512 KiB free, and both FAT read-only checks passing.

Only after a live card audit identifies the current `/dev/diskN`, generate the
session candidate plan:

```sh
python3 mainline/scripts/generate-v10-p1-write-plan.py \
  --candidate-dir mainline/out/r46h-v10-p1-candidates/r46h-v0.10-p1-one-shot \
  --device /dev/diskN \
  --confirm-device /dev/diskN
```

Start Card Agent with profile
`hl-r46h-v22-g92-31719424000-v1`, the printed plan and its SHA-256. Before
execution, `hash-raw boot` must equal the candidate receipt's
`base_image_sha256`. After the only `write-v10-one-shot-boot-p1` operation, a
fresh full p1 hash must equal the candidate `image_sha256`, and the referenced
write-status file must contain `state=WRITE_COMPLETE` and
`safe_to_boot=yes`.

The new boot file is used only from a UART-interrupted U-Boot session. Do not
run `saveenv`, replace active `boot.ini`, or call the generic switch-boot path.
An ordinary reset must continue to load the frozen v0.8 baseline.
